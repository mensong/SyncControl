# 边缘切换策略（Edge Switch Policy）

## 背景

现状是鼠标一旦接触屏幕边缘就立即切换屏幕控制，容易误触发。为此引入可配置的切换策略：要求鼠标与屏幕边缘完成"特征动作"后才切换。

## 三种预设模式

| 模式 | 行为 | 参数 |
|---|---|---|
| `immediate` | 碰边立即切换（现有行为，**默认模式**） | 无 |
| `bump` | 在时间窗口内同一边缘累计碰撞次数达到阈值才切换 | `bumpWindowMs`（默认 1000）、`bumpCount`（默认 2，即"双碰"） |
| `dwell` | 光标贴住边缘持续一段时间才切换 | `dwellMs`（默认 500） |

## 配置

通过 IPC 命令下发：

```json
{
  "type": "set_switch_policy",
  "switchMode": "dwell",
  "bumpWindowMs": 1000,
  "bumpCount": 2,
  "dwellMs": 500
}
```

- `switchMode`：`immediate` | `bump` | `dwell`。与 `service-config.json` 落盘键名一致。
- GUI 设置区可调整模式与参数，`ServiceConfigStore` 持久化，修改后防抖 300ms 发送，应用启动时恢复上次配置并发送。

## 判定细节

### "碰撞"的定义（防抖核心）

碰边不能按"收到一个边缘位置的事件"来算——光标顶在边缘不动时系统不会持续产生事件，而贴着边缘滑动会产生一串边缘事件。因此定义：

- **碰撞 = 一次"由内向外"的冲击**：光标上一次位置在边缘内侧 ≥ 8px（回弹臂距），当前位置到达边缘，才算一次碰撞。
- 光标贴着边缘平行滑动不产生新碰撞；顶在边缘不动也不产生新碰撞。
- 光标拉回内侧超过 8px 后再次撞边，计数 +1。
- **按边缘分别计数**：左边缘的碰撞不计入右边缘；跨边缘移动重置计数。同时要求碰撞位置在边缘上的相对位置接近（±10%），防止"沿上边缘扫到角落"被误算成两次碰撞。
- 回弹臂距 8px、位置容差 ±10% 为代码常量，暂不暴露到 UI。

### bump 模式的滑动窗口

记录该边缘最近一次碰撞时间，新碰撞到来时：距上次碰撞 ≤ `bumpWindowMs` 则计数 +1，否则重置为 1。计数达到 `bumpCount` 即切换并清零。全部在钩子事件内完成，不需要定时器。

### dwell 模式的定时器

低级钩子只在有鼠标事件时触发——光标静止贴边时不会有事件送进来，纯靠钩子无法实现"停留超时"。因此：

- 光标到达边缘且该边缘有有效路由时，在 InputCapture 的消息窗口上 `SetTimer(dwellMs)`；
- `WM_TIMER` 触发时用 `GetCursorPos`（本地）/ `m_remoteX/Y`（远程）复查光标仍在该边缘，满足则切换；
- 光标离开边缘区立即 `KillTimer` 取消；
- 贴边平行滑动不取消计时（只要还在边缘区）。

### 空隙段行为不变

边缘段无路由（gap）时，现有逻辑是立即把光标钳回内侧 1px 并吞掉事件，该防漏光标行为保持原样，不走策略判定——gap 永远不可切换，计数无意义。

### 本地与远程对称

- 本地→远程：`WM_MOUSEMOVE` 分支中策略返回 `Switch` 才调 `trySwitchToRemote`，`Pending/None` 时放行事件。
- 远程→远程 / 远程→本地：`handleRemoteEdge` 前套同一策略；远程侧的"拉回内侧"由虚拟坐标 `m_remoteX/Y` 判定，dwell 定时器共用同一个。

## 实现范围

1. `core/src/layout/EdgeSwitchPolicy.{h,cpp}` — 状态机（纯逻辑）；
2. `InputCapture.{h,cpp}` — 两条切换路径接入策略 + dwell 定时器（`SetTimer`/`WM_TIMER`）+ 策略 setter；
3. `Service.cpp` — IPC `set_switch_policy` 分支 + 启动参数透传；
4. GUI — 设置 UI、`ServiceConfigStore` 持久化、IPC 发送；
5. 构建验证：CMake 编译 core、dotnet 编译 GUI。

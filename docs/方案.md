# SyncControl 完整方案

## 1. 需求概述

- 多台 Windows 电脑网络互连（可能跨网段）
- 电脑 A 连着物理鼠标和键盘（主控端），其他电脑无鼠标键盘（被控端）
- 用电脑 A 的鼠标键盘无缝控制所有电脑
- 鼠标触碰屏幕边缘时切换到相邻电脑，切换关系由 GUI 布局决定
- 一条屏幕边缘可以分成多段，分别连接不同电脑，鼠标位置比例决定切换目标
- 共享剪贴板：文本切换时即传输；文件在粘贴时按需传输
- 动态增减被控端，GUI 自由摆放矩形定义布局
- C++ 实现核心服务（低延迟），C# WPF 实现 GUI 管理界面

## 2. 布局模型

### 2.1 矩形摆放

GUI 画布上有一个中心矩形（主控电脑）和周围若干矩形（被控电脑），用户自由拖拽摆放。两个矩形的边贴合关系决定鼠标切换方向。

```
        +------+
        |  C   |
        +------+
+------+ +------+ +------+
|  A   | |Master| |  B   |
+------+ +------+ +------+
        +------+
        |  D   |
        +------+
```

- Master 右边贴合 B 的左边 -> 鼠标从 Master 屏幕右边缘移出，切换到 B
- Master 上边贴合 C 的下边 -> 鼠标从 Master 屏幕上边缘移出，切换到 C
- B 上边贴合 C 的右边 -> 鼠标从 B 上边缘移出，切换到 C（被控端之间也能互切）
- 每个矩形的 4 条边各自可以有一个或多个段，每段映射到 0 或 1 个相邻矩形

### 2.2 一条边连接多台电脑

中心矩形的一条边可以被多个被控端矩形的边贴合，形成多个段：

```
  +------+      +------+
  |  E   |      |  F   |
  +------+      +------+
+--------------------------+
|        Master            |
+--------------------------+
  <-E->   <-空->  <-F->
```

Master 上边被分成两段：左段贴合 E 的下边，右段贴合 F 的下边。鼠标从 Master 上边缘移出时：
- 如果 X 坐标落在左段范围 -> 切换到 E
- 如果 X 坐标落在右段范围 -> 切换到 F
- 如果落在中间空隙 -> 不切换（鼠标限制在边缘内侧）

坐标换算按段内比例映射，而非整条边的比例。

### 2.3 坐标换算示例

```
GUI 画布:
    +------+        +------+
    |  E   |        |  F   |
    +------+        +------+
  x=100..300       x=400..600
  +------------------------------+
  |          Master              |
  +------------------------------+
  x=100..700 (width=600)

Master 上边:
  E 段: rangeStart = (100-100)/600 = 0.0,  rangeEnd = (300-100)/600 = 0.333
  F 段: rangeStart = (400-100)/600 = 0.5,  rangeEnd = (600-100)/600 = 0.833
  空隙: 0.333~0.5 (不切换)

鼠标在 Master 屏幕上边缘, mouseX = 200 (屏幕宽 1920):
  globalRatio = 200/1920 = 0.104 -> 落在 E 段 [0.0, 0.333)
  localRatio = (0.104 - 0.0) / (0.333 - 0.0) = 0.312
  targetX = 0.312 * E.screenW
  targetY = E.screenH - 1  (从 E 下边进入)

鼠标在 Master 屏幕上边缘, mouseX = 960:
  globalRatio = 960/1920 = 0.5 -> 落在空隙 [0.333, 0.5)
  不切换, 鼠标限制在边缘内侧
```

### 运行模式

每台电脑上运行的 C++ 服务是同一个二进制，通过角色区分：

- **主控模式（电脑 A）**：安装低级钩子捕获输入，检测边缘切换，通过网络向被控端发送指令
- **被控模式（其他电脑）**：接收网络指令，用 SendInput 模拟输入，监听剪贴板变化并上报

主控端和被控端之间是星型拓扑：主控端与每个被控端各维护一条 UDP 通信通道（无连接，靠心跳维持活跃状态）。

## 4. 模块详细设计

### 4.1 输入捕获模块（主控端）

使用 `SetWindowsHookEx` 安装全局低级钩子：

- `WH_MOUSE_LL`：捕获鼠标移动、按键按下/抬起、滚轮
- `WH_KEYBOARD_LL`：捕获按键按下/抬起

#### 鼠标事件覆盖范围

| 事件 | 钩子消息 | 说明 |
|---|---|---|
| 鼠标移动 | `WM_MOUSEMOVE` | 高频，需合并节流 |
| 左键按下/抬起 | `WM_LBUTTONDOWN` / `WM_LBUTTONUP` | |
| 右键按下/抬起 | `WM_RBUTTONDOWN` / `WM_RBUTTONUP` | |
| 中键按下/抬起 | `WM_MBUTTONDOWN` / `WM_MBUTTONUP` | |
| 侧键 X1 按下/抬起 | `WM_XBUTTONDOWN` / `WM_XBUTTONUP` (XBUTTON1) | 后退键 |
| 侧键 X2 按下/抬起 | `WM_XBUTTONDOWN` / `WM_XBUTTONUP` (XBUTTON2) | 前进键 |
| 垂直滚轮 | `WM_MOUSEWHEEL` | delta 值传输 |
| 水平滚轮 | `WM_MOUSEHWHEEL` | delta 值传输 |

#### 核心逻辑

```
鼠标移动事件:
  if 当前焦点在本地 (Master):
    if 鼠标触碰屏幕边缘:
      计算鼠标在该边缘上的位置比例 r (0.0~1.0)
      查边缘路由表: 该边缘上 r 所在的段 -> 目标被控端 T?
      if T 存在:
        计算切换后的坐标 (按段内比例换算)
        发送 SWITCH 指令给 T (包含初始坐标)
        隐藏本地光标
        当前焦点 = T
        return (吞掉该事件)
      else:
        // r 落在空隙段，不切换，鼠标限制在边缘
        return (吞掉, 将鼠标位置回退到边缘内侧 1px)
    else:
      正常处理 (不吞)
  else:
    // 焦点在远程，所有鼠标事件转发给对应被控端
    发送对应指令给当前焦点被控端
    return (吞掉)

鼠标按键事件 (左/右/中/X1/X2 按下或抬起):
  if 当前焦点在本地:
    不处理 (正常传递给本地系统)
  else:
    转发对应 MOUSE_BUTTON 指令给当前焦点被控端
    return (吞掉)

滚轮事件 (垂直/水平):
  if 当前焦点在本地:
    不处理
  else:
    转发 MOUSE_WHEEL 指令 (含方向 + delta) 给当前焦点被控端
    return (吞掉)

键盘事件:
  if 当前焦点在本地:
    不处理 (正常传递给本地系统)
  else:
    转发键盘指令给当前焦点被控端
    return (吞掉)
```

#### 性能要点

- 鼠标移动事件频率可达 125~1000Hz，钩子回调中只做轻量处理（查表 + 序列化 + send），不做重逻辑
- 鼠标移动指令做合并节流：如果发送队列里已有未发出的 MOUSE_MOVE，直接替换为最新值，不堆积

### 4.3 屏幕布局图 & 边缘路由器

#### 数据结构

```cpp
struct ScreenNode {
    std::string id;          // 电脑唯一标识
    std::string hostname;
    std::string ip;
    int screenW;             // 屏幕分辨率
    int screenH;
    Rect layoutRect;         // GUI 画布上的矩形位置 (仅主控端用于路由计算)
};

enum class Edge { Top, Bottom, Left, Right };

// 边缘段：一条边的一段区域，映射到一个目标电脑
struct EdgeSegment {
    Edge  fromEdge;          // 本屏幕的哪条边
    float rangeStart;        // 沿该边的起始比例 (0.0~1.0)
    float rangeEnd;          // 沿该边的结束比例 (0.0~1.0)
    std::string toId;        // 目标电脑 id
    Edge  toEdge;            // 进入目标电脑的哪条边
};

// 每台电脑的 4 条边，每条边由若干 EdgeSegment 组成
// 段之间可以有空隙 (不映射到任何目标)
struct ScreenRouting {
    std::string screenId;
    std::vector<EdgeSegment> segments[4];  // [Top, Bottom, Left, Right]
};
```

#### 路由表生成（由 C# GUI 根据矩形摆放位置计算）

对屏幕 S 的某条边 E，找出所有与该边贴合的其他矩形：

```
以 S 的上边 (Top) 为例:
  for 每个其他矩形 T:
    if T 的下边 与 S 的上边 在 Y 方向距离 < 阈值 (如 5px):
      计算 X 方向的重叠区间 [overlapStart, overlapEnd]
      if 重叠区间存在:
        将重叠区间归一化到 S 上边的 [0.0, 1.0] 比例:
          segStart = (overlapStart - S.x) / S.width
          segEnd   = (overlapEnd   - S.x) / S.width
        创建 EdgeSegment {
          fromEdge:   Top
          rangeStart: segStart
          rangeEnd:   segEnd
          toId:       T.id
          toEdge:     Bottom  (从 T 的下边进入)
        }
  按 rangeStart 排序所有段
  // 段之间可能有空隙，空隙处不切换
```

同理处理 S 的下边（找其他矩形的上边贴合）、左边（找其他矩形的右边贴合）、右边（找其他矩形的左边贴合）。

#### 边缘查询

```cpp
// 鼠标触碰屏幕 S 的边 E，在边上的位置比例为 r
// 返回目标段，或 nullptr (空隙处不切换)
EdgeSegment* lookupRoute(ScreenRouting& routing, Edge edge, float ratio) {
    for (auto& seg : routing.segments[edge]) {
        if (ratio >= seg.rangeStart && ratio < seg.rangeEnd) {
            return &seg;
        }
    }
    return nullptr;
}
```

#### 坐标换算（按段内比例）

```cpp
// 从屏幕 S 的边 E 切换到目标 T 的边 E'
// 鼠标在 S 边 E 上的全局比例为 globalRatio
// 段范围为 [seg.rangeStart, seg.rangeEnd]

// 1. 计算段内比例 (0.0~1.0)
float localRatio = (globalRatio - seg.rangeStart)
                 / (seg.rangeEnd - seg.rangeStart);

// 2. 根据切换方向计算目标坐标
Point targetPos;

if (水平切换: S 右边 -> T 左边) {
    // S 右边的比例 = 鼠标 Y / S.screenH
    targetPos.x = 0;                    // 从 T 左边进入
    targetPos.y = localRatio * T.screenH;
}
else if (水平切换: S 左边 -> T 右边) {
    targetPos.x = T.screenW - 1;        // 从 T 右边进入
    targetPos.y = localRatio * T.screenH;
}
else if (垂直切换: S 上边 -> T 下边) {
    // S 上边的比例 = 鼠标 X / S.screenW
    targetPos.x = localRatio * T.screenW;
    targetPos.y = T.screenH - 1;        // 从 T 下边进入
}
else if (垂直切换: S 下边 -> T 上边) {
    targetPos.x = localRatio * T.screenW;
    targetPos.y = 0;                    // 从 T 上边进入
}
```

### 4.4 网络传输层

#### 协议选择

| 通道 | 协议 | 理由 |
|---|---|---|
| 控制通道（握手/心跳/配置下发） | UDP + KCP 可靠层 | 需要可靠性，KCP 比 TCP 延迟低 30%~50% |
| 输入指令-鼠标移动 | 纯 UDP（不可靠） | 高频、丢包无所谓，下一帧修正，零 ACK 开销 |
| 输入指令-鼠标按键/滚轮/键盘 | UDP + KCP 可靠层 | 必须可靠，丢包会导致按键卡死/漏触发 |
| 剪贴板文本 | UDP + KCP 可靠层 | 必须可靠到达 |
| 文件传输 | TCP | 大块数据流，TCP 流式传输更高效，且需可靠有序 |

**KCP 简介**：KCP 是基于 UDP 的可靠传输协议，通过选择性 ACK + 快速重传机制实现比 TCP 更低的延迟。牺牲约 10%~15% 额外带宽换取延迟优势，适合实时交互场景。参数调优后 LAN 内单向延迟可 <0.3ms。

**通道分离**：同一 UDP 端口上复用两条逻辑通道：
- **可靠通道（KCP）**：握手、心跳、键盘事件、鼠标按键/滚轮、剪贴板文本、切换指令 — 保证到达和顺序
- **不可靠通道（纯 UDP）**：鼠标移动 — fire-and-forget，零 ACK 开销，最低延迟

消息通过类型字段区分走哪条通道。文件传输单独走 TCP 连接，与 UDP 通道独立。

#### 消息格式（二进制，紧凑）

```
[2字节 消息类型][2字节 payload长度][N字节 payload]

消息类型:
  0x01  HANDSHAKE_REQUEST     // 主控->被控，握手
  0x02  HANDSHAKE_RESPONSE    // 被控->主控，握手回应(含屏幕分辨率等)
  0x03  HEARTBEAT             // 双向心跳
  0x10  MOUSE_MOVE            // x, y (绝对坐标)
  0x11  MOUSE_BUTTON          // button(0=左/1=右/2=中/3=X1/4=X2), action(0=down/1=up)
  0x12  MOUSE_WHEEL           // direction(0=垂直/1=水平), delta
  0x20  KEY_DOWN              // vk_code, scan_code
  0x21  KEY_UP                // vk_code, scan_code
  0x30  SWITCH_IN             // 进入此被控端, 初始x, y
  0x31  SWITCH_OUT            // 离开此被控端
  0x40  CLIPBOARD_TEXT        // 文本内容(UTF-8)
  0x41  CLIPBOARD_FILES_META  // 文件列表元信息(文件名+大小)
  0x42  CLIPBOARD_FILE_DATA   // 文件数据块(分片传输)
  0x43  CLIPBOARD_REQUEST     // 请求获取剪贴板内容(粘贴时触发)
```

**消息通道路由**：

| 消息类型 | 通道 | 说明 |
|---|---|---|
| HANDSHAKE_REQUEST/RESPONSE | UDP + KCP 可靠通道 | 握手必须可靠 |
| HEARTBEAT | UDP + KCP 可靠通道 | 心跳需可靠检测连接状态 |
| MOUSE_MOVE | 纯 UDP 不可靠通道 | 高频，丢包无所谓 |
| MOUSE_BUTTON / MOUSE_WHEEL | UDP + KCP 可靠通道 | 按键/滚轮必须可靠 |
| KEY_DOWN / KEY_UP | UDP + KCP 可靠通道 | 键盘必须可靠 |
| SWITCH_IN / SWITCH_OUT | UDP + KCP 可靠通道 | 切换指令必须可靠 |
| CLIPBOARD_TEXT | UDP + KCP 可靠通道 | 文本必须可靠到达 |
| CLIPBOARD_FILES_META | UDP + KCP 可靠通道 | 元信息小且必须可靠 |
| CLIPBOARD_REQUEST | UDP + KCP 可靠通道 | 请求必须可靠到达 |
| CLIPBOARD_FILE_DATA | TCP 文件通道 | 大块数据，走 TCP 流式传输 |

**鼠标按键编码**：MOUSE_BUTTON 消息的 button 字段取值 0=左键、1=右键、2=中键、3=侧键X1、4=侧键X2，完整覆盖所有鼠标按键。

**鼠标移动优化**：发送端维护一个"待发 MOUSE_MOVE"槽位，新事件到来时直接覆盖旧值。一个定时器（或每次 send 后清空）保证最新位置总能发出。这样即使鼠标高频移动，网络上也不会堆积。

### 4.5 剪贴板 & 文件传输模块

#### 文本剪贴板

- 主控端监听 `WM_CLIPBOARDUPDATE`（`AddClipboardFormatListener`）
- 当焦点从电脑 X 切换到电脑 Y 时，主控端读取本地剪贴板（如果 X 是 Master）或向 X 请求剪贴板内容，然后发送给 Y
- 被控端收到 `CLIPBOARD_TEXT` 后，打开剪贴板写入文本

#### 文件剪贴板

- 复制文件时，剪贴板里存的是文件路径列表（`CF_HDROP` 格式）
- **不在切换时立即传输文件**，而是**在粘贴时按需传输**：

```
1. 用户在电脑 X 上复制文件
   -> X 的剪贴板记录文件元信息（文件名、大小、路径）

2. 鼠标切换到电脑 Y
   -> 只传输文件元信息列表（CLIPBOARD_FILES_META）
   -> Y 的剪贴板被设置为自定义延迟格式（含元信息但不含实际数据）

3. 用户在 Y 上执行粘贴（Ctrl+V）
   -> Y 检测到粘贴操作，向 X 发送 CLIPBOARD_REQUEST

4. X 收到请求，通过 TCP 分片发送文件数据（CLIPBOARD_FILE_DATA，每片 64KB）

5. Y 收到完整文件数据，写入本地临时目录，完成粘贴操作
```

这样大文件只在真正粘贴时才传输，避免每次鼠标切换都传文件。

### 4.6 IPC 模块（C++ <-> C#）

C# GUI 和 C++ 服务在同一台电脑上通过 **Named Pipe** 通信：

```
\\.\pipe\SyncControl
```

IPC 消息（JSON 格式，简单清晰）：

```json
// GUI -> Service
{ "type": "start_master", "layout": { ... } }   // 启动主控模式 + 下发布局
{ "type": "start_slave" }                        // 启动被控模式
{ "type": "stop" }                               // 停止
{ "type": "update_layout", "layout": { ... } }   // 更新布局（运行时热更新）
{ "type": "get_status" }                         // 查询状态

// Service -> GUI
```

## 6. 关键流程时序

### 6.1 鼠标边缘切换（多段边）

```
Master 鼠标移动 -> 钩子回调
  -> 检测触碰上边缘, mouseX = 960, 屏幕宽 1920
  -> globalRatio = 960 / 1920 = 0.5
  -> EdgeRouter.lookup(Master, Top, 0.5)
    -> 遍历 Master 上边的段:
       段1 [0.0, 0.333) -> E   (0.5 不在此段)
       段2 [0.5, 0.833) -> F   (0.5 在此段) OK
    -> 返回段2, 目标 = F
  -> localRatio = (0.5 - 0.5) / (0.833 - 0.5) = 0.0
  -> targetX = 0.0 * F.screenW = 0
  -> targetY = F.screenH - 1 (从 F 下边进入)
  -> 发送 SWITCH_IN 给 F (x=0, y=F.screenH-1)
  -> 吞掉本地鼠标事件，隐藏本地光标
  -> 当前焦点 = F

F 收到 SWITCH_IN
  -> 移动光标到 (0, F.screenH-1)
  -> 后续 MOUSE_MOVE / MOUSE_BUTTON / MOUSE_WHEEL / KEY_DOWN / KEY_UP 直接注入
```

### 6.2 鼠标落在空隙段

```
Master 鼠标移动 -> 钩子回调
  -> 检测触碰上边缘, globalRatio = 0.4
  -> EdgeRouter.lookup(Master, Top, 0.4)
    -> 段1 [0.0, 0.333) -> E   (0.4 不在此段)
    -> 段2 [0.5, 0.833) -> F   (0.4 不在此段)
    -> 返回 nullptr (空隙)
  -> 不切换, 将鼠标位置回退到边缘内侧 1px
  -> 鼠标"卡"在边缘，不会穿透
```

### 6.3 剪贴板文本切换

```
用户在 Master 复制文本
  -> ClipboardMonitor 检测到 CF_UNICODETEXT
  -> 缓存文本内容

鼠标切换到 B
  -> Master 读取缓存的剪贴板文本
  -> 发送 CLIPBOARD_TEXT 给 B (UTF-8)

B 收到 CLIPBOARD_TEXT
  -> OpenClipboard + SetClipboardData(CF_UNICODETEXT)
  -> 用户在 B 上 Ctrl+V 即可粘贴
```

### 6.4 剪贴板文件按需传输

```
用户在 Master 复制文件 (CF_HDROP)
  -> ClipboardMonitor 提取文件路径列表
  -> 生成文件元信息 (文件名 + 大小)

鼠标切换到 B
  -> 只发送 CLIPBOARD_FILES_META 给 B (仅元信息，不传文件体)

B 收到 CLIPBOARD_FILES_META
  -> 设置剪贴板为自定义延迟格式 (记录元信息)
  -> 用户看到可以粘贴

用户在 B 上 Ctrl+V
  -> B 检测粘贴触发
  -> 发送 CLIPBOARD_REQUEST 给 Master (请求文件数据)

Master 收到 CLIPBOARD_REQUEST
  -> 读取文件，分片发送 CLIPBOARD_FILE_DATA (每片 64KB)

B 收到所有 CLIPBOARD_FILE_DATA
  -> 写入本地临时目录
  -> 完成粘贴操作 (Explorer 文件操作)
```

### 6.5 启动流程

```
1. 各电脑启动 C++ 服务 + C# GUI
2. 主控端 GUI: 用户在布局编辑器中添加被控端、摆放矩形、点击"开始控制"
3. 主控端 GUI -> IPC -> C++ 服务: start_master + 布局配置(含边缘段路由表)
4. 主控端 C++ 服务: 安装低级钩子，向每个被控端建立 UDP + KCP 连接
5. 被控端 C++ 服务: 接受连接，回复 HANDSHAKE_RESPONSE (含屏幕分辨率)
6. 主控端更新布局图中各被控端的实际分辨率
7. 主控端开始捕获输入，系统进入工作状态
```

### 6.6 被控端动态增减

```
运行时新增被控端:
  -> 新电脑启动服务 (被控模式)，监听端口
  -> 主控端 GUI: 添加新矩形，填入 IP，摆放位置
  -> GUI 的 RoutingBuilder 重新计算所有受影响边的段
  -> GUI -> IPC -> C++ 服务: update_layout (含新路由表)
  -> C++ 服务: 向新 IP 发起 UDP + KCP 连接 + 握手
  -> 连接成功 -> GUI 显示绿色状态，边缘路由表更新
  -> 连接失败 -> GUI 显示红色，提示检查网络

运行时删除被控端:
  -> GUI 删除矩形 -> RoutingBuilder 重新计算路由表
  -> update_layout
  -> C++ 服务: 断开对应 UDP + KCP 连接，路由表移除该节点所有段
  -> 如果当前焦点在该节点，焦点切回 Master
```

## 7. 安全性考虑

- **握手认证**：主控端连接被控端时携带预共享密钥（首次配置时生成），被控端校验通过才接受连接
- **绑定端口**：被控端只监听主控端指定的 IP（或 0.0.0.0 + 密钥校验）
- **文件传输路径校验**：被控端写入文件时限制在临时目录，防止路径穿越

## 8. 性能优化要点

1. **KCP 快速重传**：KCP 配置 `nodelay=1, interval=10, resend=2, nc=1`，比 TCP 延迟低 30%~50%
2. **鼠标移动走纯 UDP**：零 ACK 开销，fire-and-forget，最低延迟
3. **鼠标移动合并**：发送前合并队列中的 MOUSE_MOVE，只保留最新一帧
4. **钩子回调轻量化**：只做查表 + 序列化 + send，不做文件 IO、不做字符串拼接
5. **二进制协议**：固定 4 字节头，payload 紧凑编码，不用 JSON/XML 传输入指令
6. **文件分片流水线**：64KB 分片，TCP 边读边发，接收端边收边写，不一次性加载到内存
7. **边缘段查询 O(n)**：n 为一条边上的段数，通常 <= 3，可视为常数
8. **KCP 与纯 UDP 端口复用**：同一 UDP socket 上通过消息类型区分 KCP 可靠通道和纯 UDP 不可靠通道，无需额外端口
